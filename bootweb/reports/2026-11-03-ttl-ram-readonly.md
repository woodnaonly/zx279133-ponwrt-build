## 失败记录

1. 首次 XMODEM 探针已传完，但旧工具只接受 128 字节补齐长度。该 U-Boot 会去掉 SUB 填充，长度检查因此拒绝执行。现同时接受精确长度或补齐长度，并始终校验精确载荷 CRC。
2. 首次完整服务在 SHA256 代码指纹自校验时发生同步对齐异常。故障为 `0x8900c500: stp q0,q1,[x10,#-16]`，尚未进入 NAND 读取或网口初始化。厂商异常处理自动重启；工具失效原会话，没有重放恢复指针或复位命令。
3. `-mgeneral-regs-only` 和 `-ffixed-x18` 单独使用时会被 Zig 0.14.1 后置的 CPU 特性覆盖。构建已改为显式 CPU 特性并增加机器码拒绝检查；不能仅以编译成功认定问题已解决。
4. 两次自然周期都未中断自动启动，没有加载载荷。最初怀疑初始化耗时，延长观察时间后仍失败。随后核对代码发现倒计时按约 100 毫秒一档递减，旧 Windows 串口大块读取最多等待 100 毫秒才交付数据，存在错过窗口的风险。现有数据立即读取，空闲时只等待一个字节，并记录识别/发送时序；进入内核后立即停止，不再发送字符。22:05 自然周期已验证该修正能成功中断。
5. `ram-web-cycle5` 完成网页与上传，但拒绝确认请求后关闭了仍有未读请求体的 TCP 流。lwIP 按协议发送 RST，Windows 客户端未收到可验证的 HTTP 409。已改为先半关闭发送端，再最多丢弃 200 毫秒 / 256 KiB 请求尾部；绝对服务截止仍优先。内存网帧测试覆盖缓冲区内未读数据、FIN 后到达的尾部、无响应客户端和提前截止。
6. 同一自然周期的 `ram-web-cycle5b` 重新加载后，ECC 审计及正常返回通过，但 Windows ARP 未解析成功，HTTP 连接超时。串口记录 RX 350 帧、TX 25 帧，不能据此认定网口可用；原因尚未证实。未主动复位或切换智能开关，下一次复测等待新的自然上电。
7. 静态驱动 `0x8803a4a4..0x8803a524` 读取、比较并更新 `0x88091328/0x8809132c` 两个 PHY 模式缓存；它们不在此前保存的 `AD340..AD528` 区间内。冷启动打印为 `c,c`，首次初始化后变为 `c,6`；同周期重复启动跳过了 SerDes 初始化分支。已增加该段运行时代码指纹，要求保存前值为本轮已知的 `c,c`，在 halt 后恢复并读回核对，退出证据新增 `phy_modes_restored=1`。地址来自上述指令，不猜测或改写外设寄存器；旧报告不能通过新增恢复门槛。cycle7 已实测恢复读回，但不能据此认定网络可重入。
8. `ram-web-cycle7b` 在同一自然周期重新识别、探针和装载后，PHY 缓存初值仍为 `c,c`，SerDes 初始化分支也已执行，但 HTTP 仍超时。RX 332 帧、TX 23 帧，ECC 哈希及全部退出恢复检查通过；网络重入的剩余原因未确定。不继续猜寄存器或主动复位，后续验收只使用新的自然上电周期。
9. `ram-web-cycle9` 的协议测试在服务工具第 128.845 秒结束，浏览器随后导航超时；新标签显示 `ERR_CONNECTION_TIMED_OUT`，没有本轮页面及按钮记录。串口第 207.616 秒完成恢复，工具正常退出。协议通过不能替代浏览器验收；尚不能把原因归为浏览器工具或设备网络中的某一方。
10. 23:41（UTC+08）浏览器控制报告无法可靠确认 Windows 当前浏览器 URL，并停止本轮 UI 操作。随后取消 cycle10 的自然上电监听；该目录只有串口打开及周期保护记录，未识别新启动、未发送命令、未装载或执行载荷。不能计作测试周期。
